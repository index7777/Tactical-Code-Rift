## Objective

Replace the production combat runtime with the refactored controller and scene while preserving the pre-replacement design as Git history, not as a second executable combat mode.

## Adopted boundaries

1. Public flow is `JourneyScene → RefactorBattleScene → JourneyScene`.
2. `legacy-combat` and `combat-refactor` entry flags are removed from the production composition root.
3. The seven route encounters remain authoritative in `EncounterCatalog`; the new bootstrap consumes them instead of duplicating node rosters in Phaser code.
4. The old combat is recoverable from tag `legacy-combat-pre-refactor-20260822` and `LEGACY_COMBAT_ARCHIVE.md`.
5. Existing visual FX files stay in the repository but are not loaded by the replacement battle scene in this batch. A minimal procedural slash cue may be used until a later FX asset review.
6. Audio must match the live main runtime: normal/elite `demo_battle01.mp3`, Boss `zone1-boss-bgm.mp3`, and the existing sword swish/impact WAV files.
7. Each encounter selects its canonical Area 01 battlefield family. No background, character, monster, card or UI asset is approved or regenerated by this batch.

## Implementation

- `createEncounterBattleBootstrap.ts` builds player/enemy vitals, the mixed timeline, canonical enemy intents, resilience state and shared deck from a route node id.
- `BattleTurnController` ends the battle when either team has no living timeline members.
- `RefactorBattleRuntime` exposes `victory`/`defeat` without duplicating resolution rules in the scene.
- `RefactorBattleScene` owns only scene data, presentation, encounter audio/background selection and return/retry navigation.
- `?qa-battle=<node-id>` is a read-only QA entry for direct encounter capture; it is not a legacy combat switch.
