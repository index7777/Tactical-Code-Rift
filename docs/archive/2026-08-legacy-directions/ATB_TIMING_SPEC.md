# P0-01 ATB 時序規格（Graybox v1）

## 實測決策

- 敵我共用唯一 ATB：每秒增量為 `speed × ATB_RATE`，滿值 1000。
- 原設計 `ATB_RATE=6.25` 使速度 8 需 20 秒，對 15–20 分鐘 Demo 太慢；graybox 暫定 `25`，速度 8 從空值需 5 秒。
- 為讓首次互動不必等待，graybox 戰鬥以玩家 700、敵人 250 ATB 開場；正式 encounter 可另定初值。
- 玩家 ATB 滿後進入 `command`；確認後進入 1200ms `charging`；完成才造成傷害並清空 ATB。
- 敵人 ATB 滿後有 450ms telegraph，再執行攻擊並清空 ATB。敵人不再同時使用另一套攻擊 CD。
- `Active`：玩家選單開啟時敵方 ATB 繼續。
- `Wait`：只在玩家 `command` 選單時暫停敵方；蓄力、動畫與受擊時不暫停。
- 取消指令回到 running，玩家 ATB 保持滿值，下一 frame 重新進 command。
- Graybox 中，敵人若在玩家蓄力完成前行動，必定使用重擊並打斷：玩家蓄力及 ATB 歸零。此為可視化驗證，不代表最終 75% 機率。
- 每次模擬最大步長 100ms，降低切頁或 frame spike 對規則結果的影響。

## 流程

`running → command → target → charging/queue → resolve → running`；任一方 HP 歸零進入 `victory/defeat`，只有 restart 可重置。

## FF6 參考方向修正

- 戰場採側視：敵方左、我方右；不再使用中央對稱儀表板。
- 敵方 ATB 隱藏；底部只呈現我方角色名稱、HP、ATB。
- ATB 滿才開啟該角色的指令視窗；選指令後必須進入目標選擇。
- 指令視窗採 FF6 類型的二欄選單，但使用本作命名與原創視覺。
- 正式四人隊伍需在 P1-04 加入多角色 ready queue 與切換已就緒角色；本次仍維持 P1-03 的一人對一敵規模。

## 橫向畫面構圖決策

- 放棄直向射擊遊戲常用的後肩／單角色前景視角；它會遮擋 16:9 橫向戰場，也不利於四人 ATB 資訊判讀。
- 採橫向側視隊列：敵方位於左側 55% 戰場，我方四人位於右側縱向錯位排列。
- 所有隊員常駐可見；目前操作者向前一步並高亮，指令窗只屬於該角色。
- 底部 HUD 約占畫面 22%，同時顯示四人 HP／ATB，適用手機橫向與 Steam。

## Graybox 驗收

Active 與 Wait 均能運行；選單暫停差異可觀察；鍵鼠、觸控、手把 action map 共用；蓄力、敵方攻擊、打斷、勝利、戰敗皆有文字與條狀態回饋。
