# 妖異鐵道 Demo 戰鬥方向與階段計畫

本文件是目前 Demo 的戰鬥視覺與 UX 權威方向。舊 ATB 文件僅保留為歷史資料；現行系統為「回合制、每回合速度、公開殺意、改線與交鋒」。

## 核心體驗

玩家能看見妖異的殺意與因果。敵方意圖不是除錯數字，而是一條指向目標的「殺生線」。玩家用提前、掩護、改線與交鋒斬斷命運，再以破綻、追刀、繼刀、崩勢與重斬完成連段。

```text
讀取殺意 → 調整時序 → 改線／交鋒 → 製造破綻
          → 追刀／側襲 → 繼刀 → 崩勢 → 終結
```

## 戰場構圖

規劃與演出使用不同座標狀態：

```text
規劃：敵方錯層待機區       中央交鋒帶       我方錯層待機區

演出：敵方待機區  敵交鋒位 | 交鋒點 | 我交鋒位  我方待機區
```

- 規劃階段角色錯層排列，方便點選與閱讀殺生線。
- 執行階段只讓當前相关角色進入中央水平交鋒帶。
- 接力採「待機位 → 同側集結點 → 水平交鋒點」，不做自由八方向移動。
- 勝方可停留、敗方被擊退；繼刀者穿過前一位身側補位。

## 殺生線視覺語法

殺生線只回答「敵人下一次準備傷害誰」。時序由上方 HUD 負責，其餘關係使用不同視覺物件。

```text
敵人 ──暗紅殺生線──▶ 目標腳下因果節點
敵人 ──紅線──▶ ⚔ ◀──青白刀路── 我方
EA ┐
EB ├─ 殺意 ×3 ─▶ PC
EC ┘
```

### 三層線體

1. 外層殺意霧：寬、暗紅、低透明度。
2. 主線因果絲：細、清楚，連接武器與腳下節點。
3. 行動脈衝：只在焦點或即將執行時沿線移動。

### 狀態

| 狀態 | 視覺 |
|---|---|
| 普通鎖定 | 25% 暗紅細線 |
| 焦點 | 100% 紅線、殺意霧與脈衝 |
| 高威脅 | 單次白紅閃光 |
| 我方刀路 | 青白線 |
| 交鋒 | 紅、青白線共同收束到刀鋒節點 |
| 掩護指令形成截刀 | 原線虛化，青白短線切入，新終點重接 |
| 堅守 | 僅能指定自身；原地架守，不生成通往隊友的刀路 |
| 無法攔截 | 切入線在交鋒點前斷裂 |
| 行動取消 | 紅線斷裂並化灰，時序圖示碎裂 |
| 側襲 | 金白弧線，僅預覽與執行時出現 |
| 繼刀 | 局部短金線，不畫成全場長線 |
| 崩勢 | 架勢物件碎裂，指向目標的線短暫收緊 |

固定使用多條水平視覺軌道避讓角色。普通線的交叉沒有規則意義；只有專用刀鋒節點代表交鋒。同目標多線預設合併為殺意節點，選中才展開。

- 掩護指令成功形成截刀後，被攔截的那一條紅色殺生線必須改接到截刀／交鋒節點，不得繼續連到原受保護角色。
- 同一目標若仍有其他未被攔截的敵方技能，只有那些殺生線繼續落到原目標；改線按敵方技能逐條計算，不能整組一起改寫。
- 被截刀的殺生線不是整條消失：敵人到截刀點的紅色前半段必須保留，只有截刀點到原目標的後半段斷開。雙殺意雙掩護時，畫面必須同時保留兩條紅色前段、兩個截刀點與兩條青白掩護刀路。
- 當同一角色承受多條殺意時，每張掩護必須綁定一個明確敵方技能槽。點受保護者只在剩餘一條可攔截殺意時自動綁定；兩條以上時必須再點敵人／該條殺生線。速度不足、重複預約或未指定技能槽的掩護不得提交，也不得降級播放普通支援跑位。
- 敵方也能用預先公開的護衛、反制或嘲諷條件改寫我方刀路：青白線改接敵方攔截者。敵人不得在看完玩家選擇後無預告換目標。
- 每次改寫只保留一個現行終點；舊終點完全斷開。只有明示「追蹤、貫穿、二次索敵」的技能能在截刀後繼續指向原目標。
- 截刀只消耗並改寫該敵方技能槽的紅色殺生線，不得隱藏其他我方指令。後續攻擊若未形成交鋒，仍以獨立青白刀路直接指向敵人；線上不顯示交鋒鎖，結算為單方面追刀。
- 繼刀不是新的敵方攻擊意圖，不新增第二條殺生線，也不在戰場浮出「接力」文字。規劃時只在既有刀路／交鋒節點後附著雙段金色刀痕；執行時第一段節點熄滅後，第二段脈衝沿同一因果位置亮起，提示下一位承接。

### 繼刀連續演出

1. 首位完成交鋒與正式斬擊後，目標停在交鋒位置並維持彈刀後仰僵直，不先回待機位。
2. 首位退場與繼刀者進場同時發生；鏡頭、敵人位置與受擊方向不得重置。
3. 第二刀命中前，目標持續保持後仰；第二刀必須有獨立揮刀、命中 FX、音效、停格與受擊加深。
4. 最後一刀命中後才結算：死亡者倒在當下戰鬥位置，存活者才被震退並返回待機位。
5. 繼刀者完成攻擊後返回自己的待機位；若雙方都有繼刀，兩側依相同節拍完成後再共同歸位。

### 截刀執行演出

1. 敵方沿原殺生方向朝受保護目標發動攻擊；敵方攻擊不能因掩護成立而省略。
2. 掩護者從側面同步切入，在原目標前方攔住路徑；原目標留在後方。
3. 敵方與掩護者同時播放攻擊／迎擊動作，在截刀點產生武器碰撞、音效、短停格與鏡頭反應。
4. 判定後播放敗方彈刀、後仰、受擊或崩勢；勝方才接續追擊。平手則雙方震開。
5. 敵方不能繞過掩護者穿到原目標身後；只有明示繞背、貫穿或追蹤技能能例外。
- 截刀點不使用固定中央交鋒座標。它必須落在敵方原攻擊路徑、受保護目標前方約一至一個半角色寬的位置；敵方沿原路徑逼近，掩護者在敵人抵達原目標前插入。鏡頭與後續繼刀沿用該截刀點，不把敵人拉回中央重演。

## 焦點規則

- 預設畫面安靜：所有殺生線 25%，不閃爍。
- 規劃階段以「目前正在下令的我方角色」作為自動焦點；只強化指向他、由他可改線攔截，以及他已提交的關係。不是每條線一起呼吸。
- 滑入或選中角色／敵人／卡牌：相關線 100%，無關線 8%。
- 點選我方：顯示指向他的殺意與可攔截對象。
- 點選敵方：顯示其目標、時序與我方可形成的交鋒。
- 執行階段分成三個生命週期：`行動宣告`只短暫顯示當前殺生線；`交鋒接觸`把線轉成斷線／改線／收束 FX；`傷害與回槽`不保留任何規劃線。回合完成畫面必須為零殺生線，下一回合公開新意圖時才重建。
- 規劃殺生線與演出 FX 必須使用不同容器。規劃層只能整層清除，不得用掃描世界物件標記的方式管理；斷線飛散等演出要複製必要幾何到 FX 層，不能延長規劃線生命週期。
- 普通行動不做整屏變暗；只降低無關角色彩度與局部對比。必殺或崩勢終結才允許強暗場。

## HP、護甲與架勢

三者不是三條同級彩色血條，而是一個「命脈」物件的三層結構。

- 角色身旁不顯示姓名、代號、頭像或身份框；角色本體輪廓與場上位置負責身份辨識。
- 身旁常駐資訊只保留命脈、護符與刀鐔架勢；狀態文字只在破綻、崩勢等事件期間短暫出現。

## 交鋒資訊生命週期

交鋒資訊採單一實例、階段接棒，不允許同一技能在相鄰階段重建成第二張卡：

1. `進場`：只顯示交鋒雙方身份。
2. `揭牌`：雙方技能卡各建立一次，基準停留 420ms 供玩家讀取名稱與最終威力。
3. `碰撞`：兩張技能卡立即淡出並銷毀，碰撞 FX 接手。
4. `判定`：只顯示一條勝負／相殺結果，不再顯示技能卡。
5. `追擊或取消`：結果條退場，畫面只保留角色與戰鬥 FX。

預覽卡、正式技能卡、判定結果分屬不同階段；任意時間最多只能存在其中一組主要資訊。

### 爽感與連攜節奏預算

- 資訊必須在碰撞前讀完；碰撞後由動作、音效、FX 與位移傳達結果，UI 不得遮住攻擊。
- 一般交鋒的判定條基準停留 320ms；只有首次教學、Boss 特殊判定或終結技可以延長。
- 同一連攜中的下一位角色直接承接前一位的鏡頭與敵方受擊位置，不完整重置鏡頭、不先回槽再出場。
- 繼刀節奏逐拍壓縮，但不得縮短到無法辨認出手者；以角色剪影、入場方向與專屬音色維持身份辨識。
- 連攜升級主要靠更強的受擊、音效層次、短停格、擊退與架勢碎裂，不靠反覆彈出卡片。
- 長停格與強暗場只保留給崩勢、必殺與連段終結，普通交鋒維持流動。

```text
PC      [護符][護符][裂]
━━━━━━━━━━━━━━  命脈 HP
       ◈ ◈ ◈ ◇ ◇  刀鐔架勢
```

### 命脈（HP）

- 紅色墨線；傷害先留下短暫白色殘影，再被吞沒。
- 低血量出現斷續與滲墨；歸零稱為「斷命」。

### 護甲（護符層）

- 視覺是貼在命脈外層的護符／甲片，不是第二條藍血條。
- 優先吸收 HP 傷害，但不保護架勢。
- 破甲撕除護符；側襲可部分繞過；歸零播放破符 FX。

### 架勢（刀鐔計）

- 金色分段刀鐔；交鋒失敗、破甲與集火使其碎裂。
- 最後一段轉朱紅並震動；歸零觸發「崩勢」。
- 崩勢取消尚未執行的行動，開放重斬終結與更強鏡頭。

### 破綻與崩勢

- 破綻：短期戰術狀態，交鋒失敗產生，允許側襲或穿甲，不一定取消行動。
- 崩勢：架勢歸零，行動取消、防禦降低，至少持續到本輪結束。

## 時序 HUD

- 上方一條橫向進度序列，左側先行動。
- 時序條永久保留，且保持「沿連續進度線排列」的本作語言，不改成等寬格子的通用 Turn Order。
- 時序條的責任降為「接下來誰先動、選牌後順序如何改變、連攜是否相鄰」；改線能否成立以殺生線上的刀鋒鎖／截斷結果為唯一主要答案。
- 常駐只顯示角色頭像、敵我色環與最終速度；不放完整卡名、技能說明或第二套卡片框。場上角色身旁則不重複頭像或代號。
- 已選牌後可在頭像外環增加一個攻／守／援類型符號；提前／延後只顯示一次方向動態與最終差值，例如 `↑2`、`↓3`，不常駐重複公式。
- 公式、基礎速度與測試控制預設隱藏；選中詳情才展開。
- 卡片改變順序後立即重排；下一個規劃者使用同一份最終順序。

## 難度與殺生線情報

- 普通：全局殺生線以低透明度存在，目前下令角色相关因果提升到 100%；适合学习全局反制。
- 困難：只顯示目前下令角色可观察、可迎击或可改线的杀生线，以及已经提交锁定的关系；不提供全局常驻图。
- 地獄不直接採用「完全移除所有意圖資訊」。若目標、路徑與時機全部隱藏，結果會變成猜測而非破解。
- 地獄候選規則為「限時見因果」：輪到角色下令時短暫揭露相关杀生线，随后只保留起点与落点；玩家仍能靠观察、记忆和时序反制。正式采用前必须通过公平性与无障碍测试。

## 正式構圖與角色比例決策

- 中央戰場是交鋒、追擊、換位與接力的表演區，至少保留畫面高度 50%；背景主體不得佔據交鋒帶的高對比前景。
- 底部卡牌與牌庫控制合計以畫面高度 20～25% 為上限；卡牌服務於戰場關係，不以放大牌面作為主要賣相。
- 敵我採錯層、不對稱待機陣形；Y 軸層次必須明顯，但不形成固定「同列即對位」的錯誤暗示。殺生線仍以實際指定目標為唯一關係。
- 角色比例依同場人數動態調整，不採固定放大倍數：1V1 可使用約 130～150px 高剪影，3V3 約 100～120px，4V4 約 82～100px。觸控命中區與 HUD 間距跟著陣形調整。
- 正式角色要求可從輪廓辨識髮型、武器、身形與衣袖／披風動勢；戰鬥 Sprite 不承擔完整立繪細節。
- 殺生線的被動狀態不呼吸、不流動；只有聚焦或即將執行的線顯示起點甦醒、因果絲流動與落點收緊，避免 4V4 全畫面持續運動。
- 交鋒鎖只在規則已形成交鋒時出現：敵方殺生線與我方刀路收束到同一刀鋒節點。普通交叉、滑過但尚未成立的關係不得顯示交鋒鎖。
- 場景以「異界列車旅程」而非「每戰列車置中」表達。Demo 優先做一套可重用的黃泉月台分層背景，再以遠景列車、鳥居、隧道或彼岸花層做低成本變體；妖市等全新場景延後到核心演出穩定後。
- Steam 主視覺截圖使用固定、可重現的 showcase 情境：三條敵方殺生線公開、玩家替目標選牌、其中一條被較快角色截刀，上方時序同步重排。此模式只固定資料，不偽造正常規則結果。

## 響應式與工具

- 邏輯畫布固定 1280×720，桌面與手機皆以橫向 16:9 FIT 顯示。
- 直向裝置顯示旋轉提示，不把完整 HUD 硬縮成直向。
- 安全區保留在四周；手機版左側常駐詳情取消，手牌橫向滑動／分頁。
- 人數加減、重新生成、座標與診斷資訊皆是開發工具，預設隱藏；按 `T` 才顯示或收起。
- 規劃中的「下一回合」同時是結束下令：已出卡指令保留，剩餘角色批次跳過且不耗牌；演出結束後同一按鈕才建立新回合。按鈕需以可用狀態或短暫回饋讓玩家知道剩餘角色將獲得跳過補償。

### P3：完整试玩循环

## 新手验收

首次接触的玩家应能回答：

1. 三秒内：现在谁要攻击谁？
2. 五秒内：选牌后在哪里发生交锋？
3. 五秒内：哪个目标最可能崩势？

若不能回答，停止增加特效，先修正视觉语法。
